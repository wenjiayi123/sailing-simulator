# 航行模拟器——七分钟完整演示脚本

用法：录制时照读“口播”，括号内只做操作，不需要念出来。

目标时长：6 分 40 秒至 7 分 20 秒。

演示顺序：系统定位 → RL 自动避障 → 国际港航判断 → 状态、动作与 reward → 无渲染训练 → checkpoint 回放 → 港口与天气 → 总结。

## 录制前准备（不念）

1. 先运行一次项目，按 C 进入训练页。
2. 选择 PPO，设置训练轮数=200、steps=800、并行环境=1、评估回合=1，点击“启动训练”。
3. 等待出现“POLICY READY // 无渲染训练完成”，然后关闭并重新运行项目。训练文件会保留。
4. 正式视频中的现场短训练使用 episodes=20、steps=100、agents=1。
5. Mac 按 Command + Shift + 5，选择“录制所选部分”，只框住 Godot 运行窗口并开启麦克风。
6. 策略回放期间不要按方向键。A/D 只用于小幅调整镜头。

---

## 00:00—00:40 先介绍这是什么

（操作：开始录制，主画面静止 2 秒。鼠标移到边缘，让小船、水面、航线、悬岩和 HUD 完整显示。轻按 A 或 D 缓慢转动镜头 1 秒，然后停住。）

口播：

> 大家好，这是我独立完成的一套智能航行模拟器原型。它把船舶动力学、航线与航点、障碍物、天气环境、驾驶遥测和强化学习训练放在了同一个可交互系统里。

> 它不是单纯的开船游戏，也不是冒充生产级船舶交通管理系统，而是面向智能航行算法验证和决策演示的研究原型：人可以驾驶，算法可以训练，训练结果还能回到三维环境中做物理执行和安全评估。

## 00:40—01:35 立即展示 RL 自动避障

（操作：按 C 打开“RL 船队控制”训练页，点击“运行测试集并渲染”。画面恢复后把鼠标移开，不要按方向键。）

口播：

> 我先直接展示核心闭环。现在加载训练后模型检查点，小船从人工操船切换到策略接管。这不是修改坐标的预制动画，而是由外部智能体下发油门与舵角，继续走原有船舶物理逻辑。

（操作：小船接近评估障碍时保持画面稳定。开始绕障时轻按一下 A 或 D，让船尾水迹、障碍物和顶部 POLICY EVALUATION 同时入画。）

口播：

> 我关注的不只是“有没有绕过去”。转向必须连续，避障要保留安全净距，之后还要回归原航线。顶部实时显示碰撞次数、最小安全净距、最大横向航迹误差和任务用时，让避障结果可以被量化。

## 01:35—02:25 国际港航视角

（操作：让小船继续自动航行。如果已经到达，让 POLICY EVALUATION // SUCCESS、GOAL REACHED 和评估指标保持在画面上。）

口播：

> 我对港口数字孪生的一个核心理解是：价值不在于把港区画得多像，而在于真实执行之前，能不能调整变量、进行假设推演、预测风险，再把经过验证的策略送回执行端。

> 新加坡海事及港务管理局的海事数字孪生，使用实时与历史数据、仿真和建模测试假设场景；新一代船舶交通管理系统使用数据分析识别交通热点，并通过高级算法和机器学习预测碰撞。我把这个范式缩小为环境快照、数据训练、安全约束、执行回放和结果评估闭环。

## 02:25—03:25 介绍不是黑盒的 RL 设计

（操作：按 C 打开训练页，鼠标依次指向 PPO、训练轮数、steps、并行环境和评估回合。点击“算法/环境设置”，缓慢滚动到 SAFETY、ENVIRONMENT 和 RANDOMIZATION 分组。）

口播：

> 训练侧提供 PPO、SAC、TD3、DQN 四种强化学习基线和 LOS-PID 控制理论基线。训练回合、步数、并行环境、随机种子、船体安全包络和地形净距都是显式配置，让实验可以复现。

> 当前无渲染环境把状态离散为目标距离、航向误差、航速比例、航点索引、最近障碍物净距和相对方位等维度。动作空间是三档油门与三档舵角组成的九个离散动作。奖励函数鼓励向目标推进和到达航点，同时惩罚无效油门、过大舵角、贴近障碍和碰撞。

> 参数台还预留了优化器、采样器、探索、奖励、安全和运行配置。当前基线算法已经连接学习率、折扣因子、探索率、动力学和障碍环境；其余是为更大训练后端保留的接口。

## 03:25—04:35 现场运行无渲染数据训练

（操作：点击参数窗口右上角“关闭”。在训练页设置 PPO、训练轮数=20、steps=100、并行环境=1、评估回合=1。确认后点击“启动训练”。）

口播：

> 现在现场运行一次短训练。系统先导出船舶动力学、位置航向、航点、岩体与箱体障碍和航行边界，再启动独立的后台训练进程。

（操作：全屏训练面板出现后，把鼠标移到画面边缘。先展示进度条和九个训练阶段，再让鼠标停在下方 metrics 区附近，不要点击。）

口播：

> 训练时系统暂停世界物理和三维渲染，只保留轻量数据面板。这样不会浪费算力渲染水面、悬岩和驾驶界面；训练完成后，再把策略交给三维场景展示。

> 训练回合、数据步数、探索率、奖励、成功率和碰撞率都从真实训练进程读取。完成后会写出逐回合指标、训练摘要、模型检查点和评估轨迹，而不是只播放一个虚假的进度条。

（操作：等待面板显示“POLICY READY // 无渲染训练完成”。出现后停留 2 秒，让观众看到最终 reward 和路线分数。）

## 04:35—05:35 用 checkpoint 驱动小船

（操作：点击训练面板右上角“播放策略”。回到 3D 场景后不要按方向键，只在必要时用 A/D 微调镜头。）

口播：

> 现在训练已经产生新的模型检查点。点击播放策略后，世界物理和三维画面恢复，评估障碍与航线重新创建，训练结果和安全屏障共同接管小船。这里完成了“环境快照、数据训练、模型检查点、船舶执行、结果评估”的完整闭环。

> 当前原型用 Stable-Baselines3 执行四种强化学习基线，并用同一数值环境执行 LOS-PID；训练后端、模型检查点、测试轨迹和 Godot 回放端彼此解耦，支持并行数值环境。

（操作：等待小船到达，让 SUCCESS / GOAL REACHED、collision、minimum clearance、max XTE 和 elapsed 停留 3 秒。）

口播：

> 一个训练回合结束后，系统会把到达状态、碰撞数、最小安全净距、最大航线偏差和用时写入报告。智能航行策略不能只有漂亮路线，还必须可验证、可比较、可复盘。

## 05:35—06:25 展示港口场景与环境变量

（操作：按 O 打开“教员控制台”。点击“简易港口”，等待航线、障碍和船舶出生点更新。再依次点击“薄雾”和“黄昏”，每次停留 2 秒；最后点击“收起”。）

口播：

> 训练闭环之外，这套系统还将场景和环境变量显式化。切换到简易港口时，变化的不只是背景模型，航线、障碍物、安全边界和船舶出生点也会同步切换，任务从开放水域航行变成更窄航道中的港口引航。

> 薄雾和黄昏也不只是换背景。系统会改变环境光、雾效、能见度、风、浪、流、潮汐和时间。这些变量可以用于泛化测试：策略不能只在晴天开阔水域有效，还要适应低能见度和狭窄港池。

（操作：控制台收起后，轻按 A 或 D 缓慢旋转镜头，让港口设施、船舶、水面、航线和 HUD 同时出现。）

## 06:25—07:05 总结个人贡献与判断

（操作：保持港口黄昏全景，鼠标移出主画面，镜头不再转动。）

口播：

> 总结一下，这个原型连通了四层能力：船舶动力学；航线、航点、障碍和遥测；天气、时间与港口任务；以及无渲染强化学习训练、模型检查点、策略回放和安全评估。

> 这个项目最想表达的不是“我做了一条会开的船”，而是我对港口智能化的一个判断：真正可用的决策系统，不能只有一个模型和一个漂亮的三维画面。它还必须让人看到环境变量、策略从哪里来、安全约束如何介入，以及每一次执行结果如何复盘。这就是我把航行可视化、强化学习训练和安全评估放在同一个系统里的原因。

> 以上就是这套智能航行模拟器的完整演示，谢谢观看。

（操作：说完后保持画面稳定 3 秒，再停止录屏。）

## 真实边界（不念）

- 当前实现是 Stable-Baselines3 单机无渲染训练和多环境采样，不是 Ray/RLlib 分布式集群训练。
- 可以说“参考 Ray/RLlib 的并行评估、checkpoint 和可恢复实验范式”，不要说“已经接入 RLlib”。
- 策略回放是训练结果加安全屏障，不要说“每一帧都是纯策略输出”。
- 参数面板中存在为更大训练后端预留的扩展项；当前 baseline 核心使用学习率、gamma、epsilon、训练规模、随机种子、动力学和环境快照。
- 定位说“智能航行 research prototype”，不要说“可直接用于生产港口调度”。

## 录制容错（不念）

1. 如果“运行测试集并渲染”不可用，先确认训练已生成 checkpoint，再重新执行测试生成 `user://rl_runs/policy_test_trajectory.json`。
2. 如果 20 回合短训练超过预定时间，可以在后期将等待段加速到 2 倍，但保留“启动训练”和 POLICY READY 两个关键画面。
3. 如果镜头转偏，用反向 A/D 慢慢恢复。
4. 如果 HUD 被误拖乱，按 Backspace 重置。
5. 如果按键没有反应，先点击一下 Godot 运行窗口，让它获得键盘焦点。
