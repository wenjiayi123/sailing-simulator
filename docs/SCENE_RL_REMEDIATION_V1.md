# 场景强化学习整改与验收

本轮训练只使用强化学习产生本船油门与舵角。新增策略不调用传统控制器，不使用专家动作兜底，不修改既有 36/44 维模型。历史失败、短训练模型和原始报告保留。

## 发现的问题

1. 原有五个高级任务完成了场景功能验收，旧取货策略的 14 次跨场景测试全部未通过完整任务门槛。加载模型、脚本控制目标船、测试专用航点遍历都不是新任务收敛证据。
2. 旧取货策略观测缺少独立横荡状态，不能承担靠泊漂移抑制；普通到点奖励没有表达船位、船首向、速度、横荡同时满足并保持的靠泊目标。
3. 岸壁比交通船更近时，旧迁移评估使用的最近障碍物信息会漏掉动态交通。新环境分别计算静态净距与交通船相对运动，并逐物理帧检测扫掠碰撞。
4. 目标船复制后再关闭碰撞太晚，狭水道对遇的本船曾被带到目标船出生位置。现在在目标船进入场景树之前隔离碰撞，等待两个物理帧再恢复；本船起点与切换回归单独留证。
5. 通用的 65% 最大正向油门限制没有给追越任务留下足够的浅水阻力和速差余量。新增实验允许强化学习使用船舶原本支持的完整正向推力，并把实际追越进度纳入奖励；会遇距离和岸距门槛保持不变。
6. 港口引航的末端航点中心落在膨胀后的实体码头内，末段直线又穿过礁石。到达圆仍有可航区域，但常规随机课程会生成已在障碍物内的起点，且末端成功反馈稀少。已增加有效课程起点检查与独立末端强化学习实验，未删除障碍、放宽到达半径或修改碰撞指标。
7. 47 维旧实验要求初始化后的神经策略先完整通关，再允许开始软演员评论家更新，导致训练长期卡在行为克隆和数据聚合阶段。新增独立纯强化学习实验直接采样环境并更新网络，保留全部悬岩、六艘交通船和原分级验证门槛。
8. 追越目标船原本只有固定油门、零舵角，在横风下持续转向岸边；这会让本船走完全部航点后仍没有真正驶过目标船。新增目标船航向、航速与航道保持 SAC 实验，并将其独立验收后用于双船强化学习实验。双船数值环境同时恢复目标船的岸壁受力，与 Godot 对所有船舶施加岸壁力的实现一致；目标船偏航或碰撞也不能计为成功追越。
9. Godot 浅水阻力、下沉量和岸壁力此前读取包含海流的对地航速，而训练环境使用对水纵荡航速。目标船原生验证显示约 0.4 米/秒的稳态偏差。现统一使用对水纵荡航速，保留原生失败回执，并重新跑受影响场景的完整闭环；未放宽航速误差门槛。

## 新增训练和接管方式

- 40 维场景观测涵盖当前/下一航点、本船位置与船首向、纵荡/横荡/艏摇、左右推进器与舵机状态、海流、静态净距、独立交通船相对位置/速度/最近会遇距离、任务类型与任务阶段。
- 神经网络直接给出油门和舵角；程序只做物理动作范围映射和任务阶段选择。港口引航的分阶段实验由航行强化学习网络与末端强化学习网络组成，两个阶段均为实际训练的网络。
- 使用同一双喷水推进三自由度动力学参数、四阶龙格库塔积分和每秒 60 次物理更新。数值加速器是物理模型的编译实现，没有控制策略；与原 Python 模型逐步对照，并在 Godot 进行实时闭环操船。
- 课程训练可改变训练起点。所有正式验证和独立测试均从完整任务起点开始，保留场景的全部障碍物、目标船、风浪流、浅水阻力和岸壁效应。
- 最后一个追越候选另行试验了训练专用的 9/13/17/20 米渐进安全距离课程；它没有进入准入目录。正式验证与独立测试始终使用原始 20 米门槛，实体碰撞几何始终保留。训练成功率不能当成正式业务验收成功率。
- 先检查完整任务，再做两组共八个扰动验证回合；模型冻结后才访问二十个独立测试种子。测试全部通过后仍需原生场景接管验收。
- 模型直接导出网络层供 Godot 推理。黄金输入对照验证导出推理与原模型动作一致；不通过录制轨迹搬移船舶来证明策略效果。
- 按 `N` 进入航行任务，应用任务后点击“启用场景强化学习”。仅通过准入的任务可启用；启用后切换到另一个已准入场景会自动匹配对应网络。未通过的候选显示原因并保持不可接管。

### 操作反馈与场景起点

点击启用会先显示橙色“正在启用强化学习…”，核验通过后保持绿色“已接管 · 点击停止强化学习”，并显示已运行时间与航点进度。按 `N` 收起面板即可观看当前三维场景的实时自主航行。再次点击按钮停止接管，停止提示会保留。

启用失败显示红色按钮和具体原因；任务运行失败或完成后保留最终状态，不再被“策略已通过验收”覆盖。重复观看时勾选“重定位船舶”，重新应用任务。下拉框只选择而未应用新任务时，面板会明确提示；若旧任务仍在运行，停止按钮仍可停止旧任务。启用等待期间更改任务会取消该次启用请求。

未通过验收的任务显示橙色“暂不可用 · 未通过策略验收”及原因。当前狭水道追越仍未通过完整任务验收，不能接管；勾选追越协议不改变策略准入结果。

联动场景时，船位由场景系统按正式场景起点复位。港口引航的任务预设保留了旧起点；面板不再用该旧起点二次覆盖场景船位。这使“应用任务”与直接切换场景使用相同的已验证起点。面板任务页可纵向滚动，避免增加状态提示后遮挡下方操作。

原生界面验收使用 `tools/godot_mission_rl_ui_acceptance.gd`，通过窗口内的鼠标输入检查七个任务的按钮、起点、接管、停止和自动换网，并实际运行一次完整靠泊。越界起点和碰撞停止分别作为拒绝提示、失败提示的界面测试条件，不计为策略通过证据。必须传入未存在的 `--output=res://...json` 路径；显示渲染时可另传 `--capture-dir=res://...` 保存截图。

## 可复核结果

当前结果以 [场景强化学习审计](../reports/mission_rl_coverage_audit_v1.json)、[策略目录](../data/rl/mission_rl_catalog_v1.json) 和每个实验目录中的 `receipt.json` 为准。`validation_history.json` 保留每轮真实成功与失败，`test_results.json` 是冻结后的独立结果，`native_validation_*.json` 记录原生逐次动作、任务门槛和物理状态。

面向使用者的汇总见 [本轮验收结果](../reports/mission_rl_remediation_results_v1.md)，未平滑的实测曲线见 [验证曲线](../reports/artifacts/mission_rl_v1/validation_curves.png)。

业务指标是完整任务成功、零碰撞、最小船间距离、岸距与富余水深、靠泊最终船位/船首向/航速/横荡、完成时间及执行器动作量。动作量只是能耗代理，没有真实燃料或电池标定，不能换算成已实现的节能金额。

## 证据范围

二十个独立回合验证的是同一场景几何下的起点、航向及小幅环境扰动，不代表跨港泛化、多随机种子训练稳定性、实船标定或现场许可。旧长滩港 45 维短训练基准、旧 47 维失败、四百一十单元泛化计划及拖轮/系泊/锚泊程序训练仍单独列示，不能用新场景结果代替它们的证据。

模拟系统继续保持 `simulation_mode=true`、`live_data_verified=false`、`production_authority=false`。原有模型、失败记录和传统控制算法保持独立；公开版本提供离线仿真代码与证据，不代表外部系统部署。
